Detailed Description

spectral_layout.py

Python-Gegenstück zu include/spectral/spectral_ring.hpp.

Wie telemetry_layout.py: byte-exakte Spiegelung des C++-Layouts. Bei jeder
Änderung an SpectralRingHeader / SpectralSlotHeader MUSS dieses File
mitgezogen werden. Der schema_version-Check unten schützt davor, ein
inkompatibles Layout still falsch zu interpretieren.

UNTERSCHIED ZU telemetry_layout.py: Die Slot-Größe ist NICHT statisch, sie
hängt von fft_size ab. Das Slot-dtype wird daher zur Laufzeit aus dem Header
gebaut (make_slot_dtype), nicht als Konstante importiert.

SEQLOCK-LESEPROTOKOLL: Anders als beim TelemetryRing (wo Slots nie
überschrieben werden) kann der Producer hier unter drop-oldest einen Slot
überschreiben, während Python ihn liest. read_frame() implementiert deshalb
das Lamport-Seqlock: seq vor und nach dem Kopieren prüfen, bei Änderung den
Frame verwerfen. Siehe die ausführliche Begründung in spectral_ring.hpp.

Ownership-Regel wie beim TelemetryRing: Python öffnet nur (create=False) und
unlinkt NIE -- der C++-Core ist Eigentümer.

np.dtype python.spectral_layout.make_slot_dtype ( int  fft_size,
int  record_stride 
) 
Baut das vollständige Slot-dtype zur Laufzeit.

Der Slot besteht aus dem festen Header, den fft_size floats und einem
Padding-Rest bis record_stride (der Producer rundet den Stride auf ein
Vielfaches von 8 auf). Das Padding wird als Bytes mitgeführt, damit das
dtype exakt record_stride groß ist und aufeinanderfolgende Slots korrekt
aneinandergrenzen.

Args:
    fft_size: Bins pro Frame, aus dem Header.
    record_stride: Bytes pro Slot, aus dem Header.

Raises:
    ValueError: wenn Header und fft_size nicht zusammenpassen.
