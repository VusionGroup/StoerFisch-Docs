Detailed Description

Closed-Loop-Regelkreis: entscheidet auf Basis der Kanal-Belegung, welchen Kanal der Störsender (Jammer) angreift. Entspricht [1.3.2]/[1.3.4] im PSP.

Der Controller ist das Herz des "spannendsten Analysepunkts" aus dem Transkript: Er schließt die Schleife zwischen Messung (ChannelTracker) und Aktor (Jammer-Zustand). Diese Klasse liefert die REINE Entscheidungslogik – ohne Hardware, ohne Threads, ohne Shared Memory -, damit sie isoliert gegen synthetische Belegungssequenzen testbar ist (was der Transkript-Plan als "Unit-Tests vor Hardware im Loop" ausdrücklich vorsah).

BEWUSST EINFACHE STRATEGIE (State Machine, nicht PID): Die konkrete Reglerstrategie ist eine fachliche Kernentscheidung der Arbeit. Diese Implementierung liefert eine nachvollziehbare, gut dokumentierte Basis-Strategie ("verfolge den energiereichsten belegten Kanal"), die als Ausgangspunkt und Vergleichsbaseline dient. Sie ist so strukturiert, dass eine anspruchsvollere Strategie (Prädiktion des Hop-Musters, PID-artige Nachführung) die decide()-Methode ersetzen kann, ohne die Schnittstelle zu ändern.

ZUSTANDSMASCHINE: Idle – Regelkreis nicht aktiv (Start-Kommando fehlt/Stop empfangen). Searching– aktiv, aber (noch) kein belegter Kanal gefunden. Tracking – ein Zielkanal ist gewählt und wird verfolgt. Lost – Ziel war da, ist aber verschwunden; kurze Haltezeit, bevor zurück zu Searching (gegen Flattern bei Hop-Lücken).
