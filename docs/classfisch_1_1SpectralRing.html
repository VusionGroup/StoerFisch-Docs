Detailed Description

Producer-Seite des Spektral-Rings.

RAII: Konstruktor legt das Segment an und initialisiert den Header; Destruktor unmappt und schließt, unlinkt aber NICHT (dafür destroy()).

Threading: genau EIN Schreiber. Vorgesehener Aufrufer ist der RX-/Control-Thread; push() ist wait-free (keine Locks, keine Syscalls) und blockiert unter keiner Policy.

Legt ein frisches Segment an. Wirft std::runtime_error bei Systemfehlern oder ungültigen Parametern.

Wie beim TelemetryRing: erst shm_unlink (Leiche eines abgestürzten Cores entfernen), dann shm_open mit O_EXCL. Ein noch angehängter Python-Prozess behält sein altes Mapping unbeschädigt und erkennt über den Inode-Wechsel, dass er verwaist ist.

Parameters
shm_namez.B. "/vusion_spectral" (führender '/' nach POSIX).
capacity_slotsAnzahl Slots. Muss Potenz von 2 sein.
fft_sizeBins pro Frame. Muss > 0 und geradzahlig sein, damit der Stride 8-Byte-aligned bleibt.
initial_policyStartwert; per setOverflowPolicy() bzw. CommandKind::SetOverflowPolicy änderbar.

Schreibt einen Frame. Blockiert nie.

Verhalten bei vollem Ring richtet sich nach der aktuell im Header gesetzten Policy (wird bei jedem Aufruf frisch gelesen):

  • DropNewest: Frame verwerfen, dropped_newest_count++, return false.
  • DropOldest: ältesten ungelesenen Frame überschreiben, dropped_oldest_count++, Frame schreiben, return true.
Parameters
binsZeiger auf fft_size Magnitudenwerte.
bin_countMuss exakt fft_size sein (sonst return false).
timestamp_nsCLOCK_MONOTONIC des Frames.
center_freq_hzMittenfrequenz des Sweeps.
Returns
true wenn geschrieben, false wenn verworfen oder bin_count falsch.
