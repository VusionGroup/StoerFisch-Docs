Detailed Description

Zero-Copy-fähiger Consumer des Spektral-Rings.

"Zero-Copy-fähig" mit Einschränkung: Der numpy-View auf den Ring ist
zero-copy, aber read_frame() macht bewusst eine KOPIE der Bins, weil das
Seqlock-Protokoll erst NACH dem Lesen feststellen kann, ob die Daten
konsistent waren. Einen View direkt weiterzugeben wäre unsicher -- der
Producer könnte ihn jederzeit überschreiben. Für den nicht-zeitkritischen
Analyse-Pfad ist die Kopie akzeptabel (eine 4-KB-FFT zu kopieren ist
vernachlässigbar gegenüber ihrer Verarbeitung).

Öffnet ein bestehendes Segment.

Args:
    shm_name: Name des Segments (führende Slashes werden entfernt).
    from_start: Wenn False (Standard, Live-Betrieb), startet der Reader
        an der aktuellen Schreibposition und sieht nur künftige Frames.
        Wenn True, startet er bei Index 0 und liest auch bereits
        gepufferte Frames -- gedacht für Offline-Auswertung eines
        gefüllten Segments und für Tests. Achtung: Bei True kann der
        Reader sofort überrundet sein, wenn der Producer den Ring
        bereits mehr als capacity-mal beschrieben hat; die
        Überrundungslogik in read_frame() fängt das ab.

◆ read_frame()

SpectralFrame | None python.spectral_layout.SpectralRingReader.read_frame (   self) 
Liest den nächsten konsistenten Frame. Blockiert nie.

Implementiert dasselbe Protokoll wie SpectralRingReader::tryPop() in
C++: Überrundung erkennen und vorspringen, dann Seqlock (seq gerade,
kopieren, seq erneut prüfen). Bei Torn Read: Frame verwerfen, zählen,
None zurückgeben (nächster Aufruf holt den nächsten Slot).

Returns:
    SpectralFrame bei Erfolg, None wenn leer ODER gerade ein Torn/Lap
    passiert ist. Der Aufrufer ruft in einer Poll-Schleife wiederholt
    auf; None heißt schlicht "jetzt gerade nichts Gültiges".
