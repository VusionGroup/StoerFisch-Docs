Detailed Description

Kanal (1): Kommandos ueber den Unix Domain Socket.

Der Core nimmt genau EINEN Client an und beantwortet Requests streng
sequentiell (40 Byte rein, 32 Byte raus). Wir serialisieren Zugriffe deshalb
ueber ein asyncio.Lock -- so kann eine langsame Antwort keine zweite Anfrage
ueberholen. Bricht der Core weg, liefert das Lesen EOF; daran erkennen wir den
Tod des Cores am zuverlaessigsten.

Zwei Implementierungen hinter demselben Protokoll: die echte Socket-Variante und
eine In-Process-Fake-Variante, die Kommandos direkt an die Fake-Telemetrie
weiterreicht (fuer ROD_FAKE=1).
