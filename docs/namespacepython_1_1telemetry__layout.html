Detailed Description

telemetry_layout.py

Python-Gegenstück zu include/telemetry/telemetry_ring.hpp.

WICHTIG: Dieses Layout muss byte-exakt mit dem C++-Header übereinstimmen.
Bei jeder Änderung an TelemetryRecord/RingHeader in C++ MUSS dieses File
mitgezogen werden -- der schema_version-Check unten schützt zumindest
davor, ein inkompatibles Layout still falsch zu interpretieren.

Ownership-Regel (siehe C++-Header): Python öffnet das Segment nur mit
create=False und ruft NIEMALS unlink()/close() mit destroy-Semantik auf.
Der resource_tracker von multiprocessing.shared_memory versucht das beim
Prozessende sonst automatisch -- das darf hier nicht passieren, da C++
Owner ist.

◆ _decode_payload()

np.void python.telemetry_layout._decode_payload ( np.void  record,
np.dtype  dtype 
)
protected 
Interpretiert die ersten `dtype.itemsize` Bytes des 64-Byte-Payloads
als das angegebene Struct.

`count=1` ist hier zwingend und nicht kosmetisch: np.frombuffer() ohne
count verlangt, dass die Puffergröße ein exaktes Vielfaches der
Elementgröße ist. Der Payload ist immer 64 Byte gross, also würde das
nur für dtypes funktionieren, deren Größe 64 teilt (z.B.
LatencyTimestamps mit 32) und für alle anderen mit
"buffer size must be a multiple of element size" fehlschlagen. Mit
count=1 wird genau ein Element gelesen und der ungenutzte Rest des
Payloads ignoriert -- was genau der Absicht entspricht, da setPayload()
auf der C++-Seite den Rest mit Nullen füllt.
